A問題

■ 考え方

英小文字からなる文字列 $S$ と正の整数 $N$ が与えられます（$|S| \geq 2N + 1$ が保証されています）。$S$ の 先頭から $N$ 文字 と 末尾から $N$ 文字 を取り除いて残った文字列を出力する問題です。

📝 ここがポイント: 「先頭 $N$ 文字と末尾 $N$ 文字を消す」とは、結局 $N + 1$ 文字目から $|S| - N$ 文字目まで（1-indexed）を取り出すのと同じです。残る文字数は $|S| - 2N$ 個。$|S| \geq 2N + 1$ なので、残る文字数は必ず $1$ 以上あり、空文字列になる心配はありません。

一番ラクなのは substr

C++ の string には substr(開始位置, 長さ) があります。$0$-indexed で考えると、取り出したいのは

  • 開始位置: 先頭 $N$ 文字を飛ばすので N
  • 長さ: |S| - 2N

なので s.substr(n, s.size() - 2 * n) 一発で答えになります。

よくあるミス

  • substr の第 2 引数を「長さ」ではなく「終端位置」だと勘違いする。第 2 引数は 取り出す文字数。
  • 1 文字ずつループで判定する書き方にすると、$1$-indexed と $0$-indexed が混ざって境界をミスしやすい。ループで書くなら「$0$-indexed の位置 $i$ について $N \leq i \leq |S| - N - 1$ なら出力」と整理すると間違いにくい（$i = N$ が消した後の先頭、$i = |S| - N - 1$ が消した後の末尾）。
  • s.size() は符号なし整数 (size_t) を返すので、s.size() - 2 * n を計算するときに n が大きいと…と心配になるが、本問は $|S| \geq 2N + 1$ が保証されているので必ず正の値になり問題なし。

■ 使用するアルゴリズム

  • 文字列の部分取り出し — 「先頭 $N$ 文字と末尾 $N$ 文字を削除」を「位置 $N$ から長さ $|S| - 2N$ を取り出す」と読み替え、s.substr(n, s.size() - 2 * n) で求める $O(|S|)$ の処理。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    int n;
    cin >> s >> n;

    // 先頭 n 文字を飛ばし、そこから (|S| - 2n) 文字を取り出す
    cout << s.substr(n, s.size() - 2 * n) << endl;
}

ループで書く場合

「$0$-indexed の位置 $i$ が $N$ 以上 $|S| - N - 1$ 以下なら出力」と書いても同じ結果になります。

#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    int n;
    cin >> s >> n;

    int len = s.size();
    for (int i = 0; i < len; i++) {
        if (n <= i && i <= len - n - 1) cout << s[i];
    }
    cout << endl;
}

B問題

■ 考え方

$H$ 行 $W$ 列のグリッドがあります。すべてのマス $(i, j)$ について、辺で隣接するマスの個数（上下左右に隣り合うマスのうち、グリッド内に存在するものの数）を求めて出力する問題です。

📝 ここがポイント: $H, W \leq 50$ と小さいので、全マス（最大 $50 \times 50 = 2500$ 個）を 1 つずつ見て、4 方向それぞれが グリッドの中に収まっているか を判定するだけで間に合います。これは DFS / BFS でマスを移動するときに「範囲外参照していないか」をチェックする定石 とまったく同じ判定です。

4 方向の境界判定

マス $(i, j)$（$0$-indexed、$0 \leq i \leq H-1$, $0 \leq j \leq W-1$）について、隣接マスがグリッド内にある条件は次の通りです。

  • 下 $(i+1, j)$ が存在 ⟺ i + 1 < H
  • 上 $(i-1, j)$ が存在 ⟺ i - 1 >= 0
  • 右 $(i, j+1)$ が存在 ⟺ j + 1 < W
  • 左 $(i, j-1)$ が存在 ⟺ j - 1 >= 0

当てはまった方向の数を数えれば、それがそのマスの答えです。

📝 検算のコツ: 4 隅のマスは必ず 2、外周（角以外）のマスは 3、内側のマスは 4 になります。サンプルで隅が 2 になっていなければ判定式のどこかが間違っています。

よくあるミス

  • 出力フォーマットの崩れ。各行は空白区切りで、行末は改行。「$j$ が最後の列なら改行、それ以外は空白」を 1 つの式で書くと安全（cout << a[i][j] << (j == W - 1 ? '\n' : ' ');）。
  • i + 1 <= H のように 等号を付けてしまうと、$0$-indexed では 1 つはみ出して範囲外を数えてしまう。「インデックスは $H-1$ まで」を意識する。

■ 使用するアルゴリズム

  • 全探索 + 境界判定 — 全マスを $O(HW)$ で走査し、各マスごとに上下左右 4 方向がグリッド内かを判定して個数を数える。DFS/BFS の範囲外チェックと同じ考え方。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;

int h, w;

// マス (i,j) に辺で隣接する「グリッド内の」マスの個数
int cnt(int i, int j) {
    int an = 0;
    if (i + 1 < h)  an++;   // 下
    if (i - 1 >= 0) an++;   // 上
    if (j + 1 < w)  an++;   // 右
    if (j - 1 >= 0) an++;   // 左
    return an;
}

int main() {
    cin >> h >> w;
    vector<vector<int>> a(h, vector<int>(w, 0));
    for (int i = 0; i < h; i++)
        for (int j = 0; j < w; j++)
            a[i][j] = cnt(i, j);

    for (int i = 0; i < h; i++)
        for (int j = 0; j < w; j++)
            cout << a[i][j] << (j == w - 1 ? '\n' : ' ');
}

C問題

■ 考え方

英大文字からなる文字列 $S$ が与えられます。$S$ の連続部分文字列のうち、

  • 奇数個の文字からなる
  • 中央の文字が C（長さ $l$ なら $\frac{l+1}{2}$ 文字目が C）

を満たすものがいくつあるか数えます。文字列として同じでも、抜き出した位置が違えば別々に数えます。

📝 ここがポイント: 「中央が C」という条件があるので、中央の C を 1 つ固定して数え上げる のが定石です。位置の違いで別カウントなので、各 C を中央とする部分文字列を独立に数えて足し合わせるだけでよく、重複を気にする必要がありません。

1 つの中央 C から作れる部分文字列の数

位置 $i$（$0$-indexed）にある C を中央とする部分文字列は、左右に 同じ文字数 $k$ ずつ（$k \geq 0$）伸ばした $[\,i-k,\ i+k\,]$ の形です（長さ $2k+1$ で必ず奇数、中央はちょうど $i$）。これが文字列内に収まる条件は

$i - k \geq 0$ かつ $i + k \leq n - 1$（$n = |S|$）

すなわち $k \leq i$ かつ $k \leq n-1-i$。よって取れる $k$ は $0$ から $\min(i,\ n-1-i)$ までで、個数は

$\min(i,\ n-1-i) + 1 = \min(i+1,\ n-i)$

直感的には、左に使える文字数 $(i+1)$ と 右に使える文字数 $(n-i)$ の 小さい方 までしか左右対称に伸ばせない、ということです。

例: $S = $ ABCBA の中央 C

C は $i = 2$（$n = 5$）。$\min(2+1,\ 5-2) = \min(3, 3) = 3$。実際、C / BCB / ABCBA の 3 個でちょうど一致します。

オーバーフローに注意

$|S|$ は最大 $5 \times 10^5$。全部が C のとき答えは $\sum \min(i+1, n-i) \approx n^2/4 \approx 6 \times 10^{10}$ にもなり、int（約 $2 \times 10^9$）を軽く超えます。答えと $n$ は long long で扱ってください。

■ 使用するアルゴリズム

  • 中央固定の数え上げ — 各 C の位置 $i$ について、左右へ対称に伸ばせる回数 $\min(i+1,\ n-i)$ を加算する $O(|S|)$ のアルゴリズム。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    string s;
    cin >> s;
    ll n = s.size(), ans = 0;
    for (ll i = 0; i < n; i++) {
        if (s[i] != 'C') continue;
        // 左に使える文字数(i+1) と 右に使える文字数(n-i) の小さい方
        ans += min(i + 1, n - i);
    }
    cout << ans << endl;
}

D問題

■ 考え方

黒板に整数 $X$ が 1 つ書かれています。$Q$ 個のクエリが順に来て、$i$ 番目では 2 つの整数 $A_i, B_i$ を黒板に追加し、その時点で黒板にある $2i+1$ 個の整数の中央値 を出力します。$2i+1$ は常に奇数なので、中央値は「ソートしてちょうど真ん中の 1 個」と一意に決まります。

📝 ここがポイント: 毎回ソートし直すと $O(Q^2 \log Q)$ で間に合いません。「中央値の管理」は 2 つのヒープ（優先度付きキュー）に分ける のが定石です。中央値を境にして、

  • 下半分 … 中央値以下の数を入れる 最大ヒープ（lo）
  • 上半分 … 中央値以上の数を入れる 最小ヒープ（hi）
  • 中央値そのもの … 変数 med に 1 個だけ持つ

と分けて持ち、常に 「lo のサイズ ＝ hi のサイズ」「lo の全要素 ≤ med ≤ hi の全要素」 という不変条件を保ちます。これが保たれていれば med がそのまま中央値です。

1 クエリで 2 個追加するときの場合分け

初期状態は要素 1 個（med = X、lo も hi も空）で不変条件を満たしています。各クエリで 2 個増えても要素数は奇数のままなので、サイズを左右均等に保ったまま med を更新します。$a, b$ と現在の med の関係で 3 通りに分けます。

  1. $a, b$ が 2 つとも med 以下：両方 lo へ。あふれる分として旧 med を hi へ移し、新しい中央値は lo の最大値（lo.top()）を取り出して med に。
  2. $a, b$ が 2 つとも med 以上：上の左右対称。両方 hi へ、旧 med を lo へ、新しい中央値は hi の最小値（hi.top()）。
  3. med をまたぐ（一方が以下、もう一方が以上）：小さい方を lo、大きい方を hi へ 1 個ずつ。左右が同時に 1 増えるだけなので med は変わりません。

どの場合も「lo と hi のサイズは等しい」「lo ≤ med ≤ hi」が保たれるため、更新後の med がそのまま答えになります。

なぜこれで中央値になるのか

要素数が $2k+1$ のとき、lo と hi がそれぞれ $k$ 個、間に med が 1 個。lo の全要素は med 以下、hi の全要素は med 以上なので、小さい方から数えて $k+1$ 番目（＝ちょうど真ん中）が med です。

計算量

各クエリでヒープ操作が定数回。ヒープ 1 操作 $O(\log Q)$ なので全体 $O(Q \log Q)$。$Q = 2 \times 10^5$ でも余裕で間に合います。値は最大 $10^9$ ですが、安全のため long long で扱っておくと安心です。

■ 使用するアルゴリズム

  • 2 ヒープによる中央値管理 — 中央値を境に最大ヒープ（下半分）と最小ヒープ（上半分）へ振り分け、中央値を別変数で保持。$a, b$ と中央値の大小で 3 通りに場合分けし、左右のサイズを均等に保ちながら $O(\log Q)$ で中央値を更新する。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ll x;
    cin >> x;
    int q;
    cin >> q;

    priority_queue<ll> lo;                            // 下半分: 最大ヒープ
    priority_queue<ll, vector<ll>, greater<ll>> hi;  // 上半分: 最小ヒープ
    ll med = x;                                       // 現在の中央値

    while (q--) {
        ll a, b;
        cin >> a >> b;
        if (a <= med && b <= med) {
            // 2 つとも中央値以下 → 下半分が 2 増える
            lo.push(a); lo.push(b);
            hi.push(med);                 // 旧中央値を上半分へ
            med = lo.top(); lo.pop();     // 新中央値 = 下半分の最大
        } else if (a >= med && b >= med) {
            // 2 つとも中央値以上 → 上半分が 2 増える
            hi.push(a); hi.push(b);
            lo.push(med);                 // 旧中央値を下半分へ
            med = hi.top(); hi.pop();     // 新中央値 = 上半分の最小
        } else {
            // 中央値をまたぐ → 左右に 1 個ずつ。中央値は不変
            lo.push(min(a, b));
            hi.push(max(a, b));
        }
        cout << med << endl;
    }
}
