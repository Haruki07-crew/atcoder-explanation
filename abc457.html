A問題

■ 考え方

長さ $N$ の数列 $A = (A_1, A_2, \ldots, A_N)$ と整数 $X$ ($1 \leq X \leq N$) が与えられ、$A_X$ の値を出力する問題です。

📝 ここがポイント: 問題文の添字は 1-indexed（$A_1$ が先頭）ですが、C++ の vector は 0-indexed（a[0] が先頭）です。そのまま a[x] と書くと 1 つ後ろの要素 を取ってしまうので、a[x - 1] と書く必要があります。

よくあるミス

  • cout << a[x] << endl; と書いてしまう → 1 個後ろ を見てしまう（しかも $X = N$ のときは範囲外アクセス）。
  • 配列のサイズを N + 1 にして 1-indexed で扱う方法もあるが、入力受け取りループや「vector 全体を回す」ときに混乱しやすいので、最初は 0-indexed のまま $X - 1$ で参照する 書き方をおすすめ。

■ 使用するアルゴリズム

  • 配列の要素アクセス — 入力された $X$ をそのまま使わず、必ず a[X - 1] と書いて 1-indexed → 0-indexed に変換するのがコツ。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int x;
    cin >> x;

    cout << a[x - 1] << endl;   // 1-indexed → 0-indexed
}

B問題

■ 考え方

A 問題の 2 次元バージョン です。$N$ 個の数列 $A_1, A_2, \ldots, A_N$ があり、それぞれの長さは $L_i$ で、$A_i = (A_{i,1}, A_{i,2}, \ldots, A_{i,L_i})$ です。整数 $X, Y$ が与えられたとき、$A_{X,Y}$ を出力します。

📝 ここがポイント: 各 $A_i$ は 長さがバラバラ です（このような配列を「ジャグ配列」と呼びます）。普通の vector<vector<int>> なら各行の長さを自由に変えられるので、$L_i$ を読んで a[i].resize(L_i) で必要な分だけ確保するのがきれいな書き方です。

実装の流れ

  1. vector<vector<int>> a(n); で「中身が空の vector」を $N$ 個用意。
  2. 各 $i$ について $L_i$ を読み、a[i].resize(L_i); でその行のサイズを確保。
  3. for (int j = 0; j < L; j++) cin >> a[i][j]; で要素を読み込む。
  4. $X, Y$ を読んで a[X - 1][Y - 1] を出力。

📝 ポイント: A 問題と同じく、$X$ も $Y$ も 1-indexed なので両方とも −1 しないといけません。片方だけ忘れがちなので注意。

計算量

$L_i$ の総和が $2 \times 10^5$ までなので、入力読み込みも答えの取り出しも合計 $O(\sum L_i)$ で十分間に合います。

■ 使用するアルゴリズム

  • 2 次元 (ジャグ) 配列の利用 — vector<vector<int>> + resize で行ごとに長さの違う配列を扱い、$A_{X,Y}$ を a[X - 1][Y - 1] でアクセスする。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;

    vector<vector<int>> a(n);
    for (int i = 0; i < n; i++) {
        int L;
        cin >> L;
        a[i].resize(L);                          // 行ごとに長さを確保
        for (int j = 0; j < L; j++) cin >> a[i][j];  // L 個読み込む
    }

    int x, y;
    cin >> x >> y;

    cout << a[x - 1][y - 1] << endl;   // 両方とも 1-indexed → 0-indexed
}

C問題

■ 考え方

$N$ 本のジャグ配列 $A_1, A_2, \ldots, A_N$（長さは $L_i$）と、長さ $N$ の整数列 $C$ が与えられます。これらから次のように $B$ を作ります：

  • $i = 1, 2, \ldots, N$ の順に「$A_i$ を末尾に連結」を $C_i$ 回 繰り返す。

そして、できた $B$ の $K$ 番目の値 $B_K$ を答える問題です。

素直にやると間に合わない

$C_i$ は最大 $10^9$、$L_i$ の総和は $2 \times 10^5$ なので、$B$ の長さは最大 $\sum C_i L_i \approx 10^9 \times 2 \times 10^5 = 2 \times 10^{14}$。とても作れません。$C_i$ 回コピーするループも最大 $10^9$ 回回ってしまうので、素朴に $B$ を構築するのは TLE / MLE 確定。

キーとなる観察: 「ブロック」で考える

$B$ を作るとき、$i$ 番目のステップで $A_i$ を $C_i$ 回連結 します。これを 1 つのかたまり (= ブロック $i$) と見ると、ブロック $i$ の長さは $L_i \times C_i$ です。つまり $B$ は

ブロック1 ($L_1 \times C_1$ 個) → ブロック2 ($L_2 \times C_2$ 個) → ⋯ → ブロック$N$ ($L_N \times C_N$ 個)

を順につないだだけのものです。

📝 ここがコツ: $K$ 番目の要素がどのブロックに入っているかは、ブロックを左から見ていって 長さの累積を引き算していく だけで分かります。

アルゴリズム

  1. $i = 0, 1, \ldots, N - 1$ の順に見ていく。
  2. 現在のブロックの長さは len = L[i] * C[i]。
    • もし K <= len なら、答えはこのブロック内にある。
    • そうでなければ K から len を引いて、次のブロックへ。

ブロック内のどこを見ればいい?

ブロック $i$ は $A_i$ が $C_i$ 回繰り返されたものです。$A_i$ の長さは $L_i$ なので、ブロック内の位置 $K$ ($1$-indexed) は $A_i$ の中で $((K - 1) \bmod L_i)$ 番目（0-indexed） になります。

つまり、答えは a[i][(K - 1) % L[i]]。

例: $A_1 = (10, 20, 30)$, $C_1 = 2$ のブロック

このブロックの中身は 10, 20, 30, 10, 20, 30 の 6 個。ここで $K = 5$ が来たら、$5 - 1 = 4$、$4 \bmod 3 = 1$ なので a[0][1] = 20。実際に並べた 5 番目 (1-indexed) は 20 なので合っています。

オーバーフローに注意

$L_i \times C_i$ は最大 $2 \times 10^5 \times 10^9 = 2 \times 10^{14}$ になり、int (約 $2 \times 10^9$ まで) を超えます。$K$ もこの和まで取り得るので、K, L[i] * C[i] はすべて long long で扱う 必要があります。掛け算する前に (ll) でキャストしないとそこでオーバーフローします。

■ 使用するアルゴリズム

  • ブロック分けによる位置特定 — $B$ を実際に作らず、各ブロックの長さ $L_i \times C_i$ を順に引いて $K$ がどのブロックに落ちるかを特定し、最後に a[i][(K - 1) % L[i]] で値を取り出す $O(N)$ のアルゴリズム。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ll n, k;
    cin >> n >> k;

    vector<int> L(n);
    vector<vector<ll>> a(n);
    for (int i = 0; i < n; i++) {
        cin >> L[i];
        a[i].resize(L[i]);
        for (int j = 0; j < L[i]; j++) cin >> a[i][j];
    }

    vector<ll> c(n);
    for (int i = 0; i < n; i++) cin >> c[i];

    // ブロックを左から順に見ていき、K がどのブロックに落ちるかを探す
    for (int i = 0; i < n; i++) {
        ll len = (ll)L[i] * c[i];          // ブロックの長さ (long long にキャストしてから掛ける)
        if (k <= len) {
            // K はこのブロック内。A_i は C_i 回繰り返されているので mod L[i]
            cout << a[i][(k - 1) % L[i]] << endl;
            return 0;
        }
        k -= len;                          // 次のブロックへ
    }
}

D問題

■ 考え方

長さ $N$ の数列 $A$ と整数 $K$ が与えられます。1 回の操作で「インデックス $i$ を選んで $A_i$ に $i$ を加える」（インデックス自体の値を加える！）ができ、これを最大 $K$ 回まで行います。最終的に $\min A_i$ をできるだけ大きくしたい、というのがゴールです。

📝 事前知識: この問題は 競プロ典型 90 問の "Yokan Party" と同系統の 「答えで二分探索」 問題です。Yokan Party の解説を読んでから戻ってくると、この問題の見え方が一気にクリアになります。

「答えで二分探索」とは?

欲しい答え（最終的な $\min A_i$ の最大値）を $x$ と置いたとき、$x$ には次のような性質があります：

  • $x$ が小さければ「すべての $A_i$ を $x$ 以上にする」ことは 容易（少ない操作で可能）。
  • $x$ が大きすぎると、$K$ 回の操作では足りず 無理。
  • つまり「達成可能な $x$」と「不可能な $x$」の境目が 1 つだけ存在する 単調性 がある。

この境目は 二分探索 で見つけられます。各候補 $x$ に対して「check(x) = $K$ 回以内で全要素を $x$ 以上にできるか?」が判定できれば OK。

check(x) の作り方

各 $A_i$ について考えます。インデックス $i$ ($1 \leq i \leq N$) の要素には 1 回の操作で $i$ を加えるので、$A_i$ をちょうど $x$ 以上にするのに必要な最小操作回数は

$\left\lceil \dfrac{\max(0,\ x - A_i)}{i} \right\rceil$ 回

です ($A_i \geq x$ ならそもそも不要なので $0$ 回)。これを $i = 1, \ldots, N$ について合計し、$\leq K$ なら達成可能。

📝 切り上げ割り算のテクニック: $\lceil a / b \rceil$ は (a + b - 1) / b と書ける（$a \geq 0$, $b \geq 1$ のとき）。この問題では $i$ が $1$-indexed で、コード上では i が $0$-indexed なので「実際に加える値」は i + 1。式は ((x - a[i]) + i) / (i + 1) になります。

二分探索の範囲

  • 下限 (ok): $-1$（$x$ 以下を「常に達成可能」、つまり $x = 0$ なら 0 回で OK なので確実に成功する側）。
  • 上限 (ng): $3 \times 10^{18}$ 程度。$A_i \leq 10^{18}$ で、$K \leq 10^{18}$ 回の操作で各要素は最大 $10^{18} \times N$ くらいまで増える可能性があるが、実際の最適値はもう少し低くなるので、$3 \times 10^{18}$ で安全に届きます。

オーバーフロー対策

$x$, $A_i$, 必要操作数 plu はどれも最大で $10^{18}$ 級になります。cnt + plu が long long の上限 ($\approx 9.2 \times 10^{18}$) を超える可能性があるので、足す前に

  • plu > k （単独でもう $K$ を超えている）
  • cnt > k - plu （足したら $K$ を超える）

のどちらかが成り立ったら即座に false を返すと安全です。cnt + plu > k と書いてしまうと 足し算した瞬間にオーバーフロー して間違った判定になる可能性があるので注意。

計算量

二分探索が約 $\log_2(3 \times 10^{18}) \approx 62$ 回。各回の check が $O(N)$ なので、全体で $O(N \log V)$（$V$ は探索範囲）。$N = 2 \times 10^5$ でも余裕で間に合います。

■ 使用するアルゴリズム

  • 答えで二分探索 (parametric search) — 「全要素を $x$ 以上にできるか?」という判定問題に落とし、達成可能な最大 $x$ を ok / ng の二分探索で求める。
  • 切り上げ割り算 — 各 $i$ について必要操作数を (x - A_i + i) / (i + 1) で計算（$0$-indexed なので $i + 1$ が「加える量」）。
  • オーバーフロー回避 — 累積を取るときは cnt > k - plu の形で「足す前に」判定する。

■ コード (C++)

#include <bits/stdc++.h>
using namespace std;
using ll = long long;
using ull = unsigned long long;

ll n, k;
vector<ll> a;

// 「全要素を x 以上にできるか?」の判定
bool check(ll x) {
    ull cnt = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] >= x) continue;                        // すでに x 以上なら不要
        // i は 0-indexed なので、加える量は i+1
        // 必要操作数 = ceil((x - a[i]) / (i+1)) = ((x - a[i]) + i) / (i+1)
        ull plu = (ull)((ull)x - a[i] + i) / (ull)(i + 1);

        // 足す前にオーバーフロー & K 超え判定
        if (plu > (ull)k || cnt > (ull)k - plu) return false;
        cnt += plu;
    }
    return true;
}

int main() {
    cin >> n >> k;
    a.resize(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    // ok = 達成可能な x の最大値, ng = 達成不能な x の最小値
    ll ok = -1, ng = (ll)3e18;
    while (ng - ok > 1) {
        ll m = (ng + ok) / 2;
        if (check(m)) ok = m;
        else          ng = m;
    }

    cout << ok << endl;
}
